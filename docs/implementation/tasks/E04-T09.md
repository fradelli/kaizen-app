# E04-T09 — Padronizar estrutura das páginas React

## Estado e limite

- Aplicar depois da E04-T04.
- Refatoração estrutural sem mudança visual ou regra de negócio.
- Seguir `docs/architecture/TARGET-ARCHITECTURE.md` como fonte normativa.

## Decisões

- Entradas `page.tsx` continuam Server Components e apenas compõem a rota.
- Dieta e Treino compartilham um placeholder porque já existem dois consumidores.
- O placeholder deixa de existir quando as páginas reais de E06/E07 o substituírem.
- Foundations continua como rota técnica, mas somente o exemplo de `Sheet` fica client-side.
- As seções da galeria Foundations são filhos privados porque cada uma possui responsabilidade visual identificável.
- Cada componente possui pasta própria; `components/` contém somente subpastas de componentes.
- Arquivos auxiliares pertencentes a um filho ficam na pasta desse filho, não centralizados no pai.
- Classes densas saem do JSX para `*.styles.ts`; CSS Module permanece reservado para composição que exija CSS próprio.
- Arquivos de tipos, constantes, utils e hooks só são criados quando possuem conteúdo e responsabilidade reais.

## Ordem de implementação

1. Criar e testar `FeaturePlaceholder` sem alterar o conteúdo visível.
2. Reduzir Dieta e Treino à composição server-side do componente compartilhado.
3. Criar uma pasta por seção de Foundations e mover para ela os estilos e contratos exclusivos.
4. Isolar o `Sheet` e seus imports na pasta de `FoundationsSheetExample` com `"use client"`.
5. Encapsular AppShellNavigation, seus estilos, tipos, constantes, utilitário, hook e teste.
6. Criar o validador estrutural, suas regressões e integração com a CI.
7. Tornar a composição principal de Foundations server-side e deixar a rota fina.
8. Mover os testes, adicionar cobertura do placeholder e executar todos os gates.

## Critérios de aceite

- Rotas finas e server-side.
- Estilos fora do JSX dos componentes extraídos.
- Contratos e constantes separados somente onde há responsabilidade real.
- Conteúdo e nomes acessíveis preservados.
- Nenhuma nova dependência, regra de domínio ou integração de dados.
- Gates locais integralmente verdes.
