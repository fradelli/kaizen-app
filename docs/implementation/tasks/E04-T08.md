## Regras de implementação

### Registry e credenciais

- O repositório pode versionar `@fradelli:registry=https://npm.pkg.github.com`.
- Token, PAT, valor de `NODE_AUTH_TOKEN` e linha com credencial real não entram no Git.
- Desenvolvimento local usa autenticação no perfil do usuário.
- CI usa credencial efêmera com `packages: read` somente depois que o package conceder acesso ao repositório consumidor.
- Falha de autenticação encerra a instalação; não existe fallback por cópia ou versão pública diferente.

### Fonte e tema

- Usar Inter variável de `next/font` sem declarar pesos individuais.
- Configurar `variable: "--font-inter"` e aplicar a classe gerada ao `<html>`.
- Aplicar explicitamente `className="dark"` no `<html>` além do dark-first já definido pelo CSS do package, salvo se o contrato da mesma versão demonstrar outro mecanismo obrigatório.
- O package referencia a variável; o Kaizen é o único responsável por carregar a fonte.

### CSS e Tailwind

- `globals.css` é o único ponto de importação do CSS público.
- O `@source` deve usar o caminho relativo real do `dist` publicado, nunca o repositório-fonte.
- Não criar `tailwind.config.*` se o contrato e Tailwind CSS 4 não exigirem.
- Não manter cópias locais de tokens, foco, radius, sombra ou estados que o package já fornece.
- CSS Modules permanecem permitidos apenas para layout e composição específicos do Kaizen.

### Foundations

- A rota exercita tipografia, superfícies, bordas, foco, motion reduzido, estados genéricos e primitives disponíveis.
- Cor categórica aparece somente como amostra visual por nome de cor, sem mapear dieta, treino, hábito ou tarefa.
- Cada cor tem rótulo textual; nenhuma informação depende somente de cor.
- A rota não antecipa shell, navegação final ou dados de domínio.

## Validações

```powershell
pnpm install --frozen-lockfile
pnpm format:check
pnpm lint
pnpm typecheck
pnpm test:coverage
pnpm build
pnpm list react react-dom @fradelli/ui --depth 2
git diff --check
```

Além dos comandos, inspecionar:

- instalação em checkout sem `node_modules` e sem autenticação persistida no projeto;
- CSS do build para as classes exercitadas pelo package;
- foco visível e navegação integral por teclado;
- contraste dos estados normais, hover, focus e disabled;
- viewport de 320 px, zoom de 200% e preferência por movimento reduzido;
- ausência de segredo, tarball e caminho local no diff e nos logs.

## Riscos

- Permissão insuficiente no package privado interromper instalação local ou CI.
- Release ou contrato publicado divergir da evidência de prontidão.
- `@source` ou ordem de imports remover classes necessárias.
- Peer range produzir React duplicado.
- Mudança incompatível em `0.x` chegar ao consumidor por versão flutuante.

## Rollback

- Primeira adoção: reverter a PR completa, restaurando `package.json`, lockfile, root, CSS e workflow anteriores.
- Upgrade posterior: fixar novamente a última versão exata conhecida como boa e regenerar o lockfile de forma revisada.
- Release defeituoso recebe patch no produtor; nunca sobrescrever versão, copiar sources ou relaxar o frozen lockfile.

## Contrato conhecido e evidência pendente
