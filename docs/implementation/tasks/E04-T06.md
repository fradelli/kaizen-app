# E04-T06 — Registrar adoção do Design System compartilhado

## Status do pacote

- **Ação:** aplicar somente nesta tarefa.
- **Fonte normativa:** [ADR 0001 — Fundação do Design System compartilhado](https://github.com/fradelli/design-system/blob/main/docs/decisions/0001-shared-design-system-foundation.md).
- **Estado:** implementação documental pronta para validação; não autoriza integração técnica.

## Objetivo

Registrar no Kaizen que `@fradelli/ui@0.1.0` substitui a fundação visual local planejada, sem apagar a arquitetura aprovada em E03 nem antecipar sua instalação.

## Contexto

`docs/architecture/TARGET-ARCHITECTURE.md` escolhe CSS Modules com tokens globais e rejeita Tailwind ou biblioteca de componentes. E04-T01 materializou esse estado transitório com tema claro, tokens locais e Arial. O novo ADR compartilhado define Tailwind CSS 4, Inter variável, dark-first e ownership externo de tokens e primitives.

## Decisão local obrigatória

O novo documento deve conter, no mínimo:

- status, data, tarefa e fonte normativa;
- contexto e decisões anteriores substituídas;
- decisão de consumir um package externo com versão exata;
- ownership completo de Design System e Kaizen;
- ordem de prontidão e integração;
- segurança do registry e proibição de credenciais no Git;
- validações acumuladas e rollback;
- pendências do contrato público.

Não copie paletas ou contratos que pertencem ao ADR externo. Use link normativo e registre somente as consequências específicas do Kaizen.

## Ownership obrigatório

### Design System

- tokens visuais, tipografia, cores, radius, bordas, sombras, foco e motion;
- estados visuais genéricos;
- primitives acessíveis e padrões comprovadamente compartilhados;
- CSS público e contratos de export do package.

### Kaizen

- marca, metadata, assets, shell, layouts, páginas e rotas;
- dieta, treino, hábitos, tarefas e calendário composto;
- regras, autenticação, persistência, APIs, Server Actions e providers;
- textos, i18n e mapeamento de cor categórica para conceitos do domínio;
- CSS estritamente de composição local, sem duplicar tokens ou primitives.

## Dependências

- E04-T01 concluída.
- E04-T02 concluída na branch própria; sua integração em `developer` deve preceder a PR desta tarefa.
- ADR 0001 permanece aceito e acessível no commit usado como evidência.

## Critérios de aceite

- A nova decisão substitui explicitamente “CSS Modules + tokens globais” como fundação visual exclusiva e a rejeição anterior de Tailwind/biblioteca.
- A rejeição ao monorepo é atualizada sem sugerir ausência de package compartilhado.
- E03-T04, E03-T05 e E04-T01 continuam concluídas e imutáveis em seus resultados.
- A documentação registra `0.1.0`, `@fradelli/ui/styles.css`, `@fradelli/ui/dist`, engines e peers conforme o release publicado.
- E04-T04 depende da integração definitiva e as telas de domínio dependem do shell.

## Riscos

- Duplicar o conteúdo normativo e deixar os documentos divergirem.
- Deixar de reconfirmar o contrato ao atualizar uma versão `0.x`.
- Permitir que o Kaizen volte a criar primitives locais antes do release.

## Rollback

Se a adoção for cancelada antes de E04-T08, reverter a PR documental. Se já houver consumo técnico, criar nova decisão substituta, restaurar a versão/configuração anterior e preservar esta decisão no histórico.

## Contrato conhecido e gaps que não bloqueiam esta tarefa

- versão publicada: `@fradelli/ui@0.1.0`, com pin exato futuro;
- CSS público: `@fradelli/ui/styles.css`;
- source publicado: `@fradelli/ui/dist`; o caminho relativo ao `globals.css` será comprovado em E04-T08;
- Node `>=24.20.0 <25`, React/React DOM `>=19.2.7 <20` e Tailwind CSS opcional `>=4.3.0 <5`, compatíveis com as versões planejadas do Kaizen;
- dark-first definido pelo package em `:root`; o Kaizen tornará a intenção explícita no root;
- primitives publicadas: alert, badge, button, card, field, input, label, separator, sheet e skeleton; helper `cn`;
- acesso Read do repositório foi concedido, mas autenticação local e configuração do workflow ainda precisam ser comprovadas.

O manifesto usado como evidência é o da tag `v0.1.0`, commit `3e0c23f591ff458ab9e3e74dc44bb0cdba068a03`. Mudança posterior em `main` não altera retroativamente este contrato.
