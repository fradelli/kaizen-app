Adicionar como dependências de desenvolvimento as versões exatas `ajv@8.20.0` e `ajv-formats@3.0.1`. O Ajv mantém o modo estrito, com apenas `strictRequired: false`, porque os schemas 2020-12 existentes possuem propriedades obrigatórias aceitas pelo padrão que não são repetidas em `properties`.

Matriz do workflow:

- eventos `pull_request` para `developer`, `staging`, `master` em opened, synchronize, reopened e edited;
- `permissions: contents: read`;
- cancelamento por PR para CI, nunca para deploy iniciado;
- Node/pnpm idênticos ao manifesto;
- instalação `pnpm install --frozen-lockfile`;
- nenhum segredo em PR comum;
- audit falha a partir de `moderate`;
- cada nome de job permanece estável.
- cache automático desabilitado até existir benefício medido.

O validador de governança aceita uma exceção mínima para `dependabot[bot]`: origem `dependabot/*`, destino `developer` e título `build(deps): ...` ou `build(deps-dev): ...`. A exceção remove somente ID e template humano; não remove nenhum gate técnico.

O agregador local é executado com `pnpm run ci`. O comando reduzido `pnpm ci` pertence ao próprio pnpm e equivale à instalação congelada, portanto não deve ser documentado como execução dos gates.

Os arquivos `scripts/*.test.mjs` usam o runner nativo do Node e são excluídos explicitamente da descoberta do Vitest. Isso evita execução dupla e mantém a cobertura da aplicação separada das regressões dos validadores.

Esta tarefa não configura autenticação do GitHub Packages. O package `@fradelli/ui@0.1.0` já está publicado e o repositório recebeu acesso Read, mas E04-T08 editará o workflow para conceder `packages: read` e fornecer credencial efêmera somente no momento da integração.
