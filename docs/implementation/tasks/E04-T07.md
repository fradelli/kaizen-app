# E04-T07 — Validar prontidão técnica para o Design System

## Status do pacote

- **Ação:** diagnosticar e registrar; não instalar o package.
- **Fonte:** decisão E04-T06, release `@fradelli/ui@0.1.0` e estado real do Kaizen.
- **Estado:** planejado; depende de E04-T05 e E04-T06.

## Objetivo

Emitir uma decisão GO/NO-GO sobre a instalação de `@fradelli/ui@0.1.0`, comprovando primeiro runtimes, peers, gates, CI e estratégia segura de autenticação.

## Contexto

O package privado já está publicado e o repositório consumidor recebeu acesso Read. Isso não configura autenticação local nem garante que o CI e os gates do Kaizen estejam verdes na mesma base. E04-T02 foi concluída na branch própria, mas seu resultado precisa estar integrado com E04-T05 antes deste gate. A versão planejada de React é compatível; a instalação deve aguardar esta validação.

## Escopo

- Confirmar Node 24.20.0, pnpm 11.25.0, Next.js 16.3.4, React e React DOM 19.2.8.
- Confirmar engines, peer ranges e exports publicados de `@fradelli/ui@0.1.0` sem instalá-lo.
- Confirmar que E04-T02 e E04-T05 deixaram gates locais e CI verdes.
- Definir o mecanismo futuro de registry e autenticação local/CI sem segredo no Git.
- Registrar matriz de compatibilidade, gaps e decisão GO/NO-GO reproduzível.

## Fora do escopo

- Instalar `@fradelli/ui`, Tailwind, PostCSS, fonte ou components.
- Alterar `package.json`, `pnpm-lock.yaml`, CSS, root ou workflow.
- Persistir PAT, token, `.npmrc` autenticado ou credencial de qualquer natureza.
- Construir shell, calendário ou feature.

Divergência entre o release consultado e estes dados bloqueia o GO.

## Prontidão a comprovar

- React e React DOM satisfazem `>=19.2.7 <20`.
- Node satisfaz `>=24.20.0 <25` e pnpm permanece o package manager do consumidor.
- Formato, lint, typecheck, testes, cobertura e build estão implementados e verdes.
- CI executa os mesmos gates e está pronto para receber `packages: read` em E04-T08.
- Autenticação local é tratada fora do repositório; acesso Read do repositório não é confundido com login local.
- O contrato público não exporta shell, página, rota ou conceito de domínio.

## Dependências

- E04-T05 e E04-T06 concluídas.
- Release `0.1.0` e contrato mínimo de consumo continuam disponíveis.

## Critérios de aceite

- A matriz confirma Node e React compatíveis com o package.
- Formato, lint, tipos, testes, cobertura e build passam localmente e no CI.
- A estratégia de `.npmrc`, `packages: read` e token efêmero está descrita sem segredo.
- O relatório registra o teste local de acesso como sucesso ou gap, sem expor credencial.
- O branch final não contém `@fradelli/ui`, Tailwind, `.tgz`, dependência `file:` ou mudança de aplicação.

## Validações

Executar os scripts existentes do Kaizen, incluindo:

```powershell
pnpm format:check
pnpm lint
pnpm typecheck
pnpm test:coverage
pnpm build
git diff --check
```

Registrar no relatório comandos, versões, resultados e limitações, sem logs extensos nem caminhos pessoais. Não executar instalação do package nesta tarefa.

## Riscos

- Permissão Read existir, mas a autenticação local continuar ausente.
- Workflow ainda não existir ou não executar todos os gates.
- Aprovar o GO com mudanças locais não relacionadas ou evidência incompleta.
- Mudança posterior em `0.x` ser consumida sem nova versão exata.

## Rollback

Reverter somente o relatório de prontidão. Se o contrato mudar, produzir nova evidência vinculada à nova versão; não reescrever o resultado anterior.

## Gaps já observados

- E04-T02 foi concluída na branch própria; seus gates devem ser reexecutados na base integrada usada por E04-T07;
- workflow de CI ainda ausente;
- autenticação local do GitHub Packages ainda ausente (`npm view` retornou 401 sem token);
- pins exatos de Tailwind/PostCSS e caminho relativo final de `@source` pertencem a E04-T08.
